{% load i18n %} {% comment %} The viewer's own profile as one continuous sheet: identity header, then a labelled row per setting. Reading and editing are the same markup — every value is already its own form control, read-only until the sheet switches to edit mode, so entering edit mode needs no request and nothing moves on screen. `sheet.js` flips `data-sheet-mode` and unlocks the controls; the `tw:reading:` / `tw:editing:` variants show the matching actions. Saving posts the sheet and swaps it back in place, so the response of UserUpdateView must be this partial. `profile_is_editing` keeps the server-rendered state in sync with the client one. The photo is not part of that cycle — see _profile_photo.html — so entering edit mode adds nothing to the header and the rows below it stay put. {% endcomment %}
